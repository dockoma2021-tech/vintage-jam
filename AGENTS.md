# Vintage Jam: постоянный рабочий процесс

## Репозиторий и production

- Репозиторий: `dockoma2021-tech/vintage-jam`.
- Рабочая production-ветка: `main`.
- Репозиторий автоматически публикуется через Vercel, поэтому `main` является живой production-версией сайта.
- Сохранять существующую связку GitHub → Vercel и не менять её без отдельного явного запроса пользователя.

## Начало каждой задачи

1. Работать непосредственно в ветке `main`, если пользователь явно не попросил создать отдельную ветку.
2. Перед началом любых изменений выполнить:

   ```bash
   git pull --ff-only origin main
   ```

3. Если pull завершился ошибкой, остановиться и сообщить пользователю ошибку. Не продолжать работу вслепую.

## Изменения и проверки

- Изменять только файлы, относящиеся к текущей задаче.
- Не удалять и не перезаписывать посторонние файлы.
- После внесения изменений обязательно просмотреть изменённые файлы и `git diff`.
- Выполнить все доступные и уместные для проекта проверки.
- Не отправлять в GitHub заведомо сломанную версию сайта.
- Если какая-либо проверка завершилась ошибкой, остановиться, не выполнять push и сообщить пользователю точную ошибку.

## Commit и push

Если проверки прошли успешно:

1. Добавить в индекс только нужные файлы с явным указанием путей через `git add -- <paths>`.
2. Создать понятный commit, описывающий выполненное изменение.
3. Автоматически выполнить:

   ```bash
   git push origin main
   ```

- Для обычных commit и push в рамках выполненной задачи не запрашивать у пользователя дополнительного подтверждения.
- Никогда не использовать force push (`--force`, `--force-with-lease` и аналоги).
- Не выполнять `git reset --hard`, rebase и другие потенциально разрушительные операции без отдельного явного разрешения пользователя.
- Если commit или push завершился ошибкой, остановиться и сообщить ошибку; не повторять операцию вслепую.

## Отчёт после push

После каждого push сообщить пользователю:

- что изменено;
- какие файлы изменены;
- SHA созданного коммита;
- успешно ли выполнен push.


## Передача результатов между Codex и ChatGPT

После каждой завершённой задачи создать или полностью обновить файл `.codex/HANDOFF.md`. Он должен содержать актуальный отчёт только по последней выполненной задаче и не накапливать историю предыдущих задач.

Использовать следующий формат:

```markdown
# Codex Handoff

## Task
Что было поручено.

## Result
Что фактически сделано.

## Changed files
Полный список изменённых файлов.

## Checks
Какие проверки и тесты выполнены и их результаты.

## Problems found
Обнаруженные проблемы, даже если они не исправлены.

## Decisions
Какие технические решения были приняты и почему.

## Remaining work
Что ещё осталось сделать.

## Git
Branch:
Commit SHA:
Push status:
```

Правила ведения handoff:

1. Писать достаточно подробно, чтобы другой ChatGPT мог продолжить работу без чтения истории чата Codex.
2. Если задача была только аудитом и код сайта не менялся, всё равно обновить `.codex/HANDOFF.md`.
3. Добавлять `.codex/HANDOFF.md` в тот же commit, что и изменения текущей задачи.
4. После успешных проверок выполнить commit и push в `origin/main` согласно правилам выше.
5. Не включать в handoff секреты, токены, пароли и другие credentials.
